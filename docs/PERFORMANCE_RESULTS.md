# 本机渲染优化对照（2026-10-25）

[优化实现](OPTIMIZATION.md) · [基准与命令](../examples/performance/README.md) · [验证记录](VALIDATION.md)

Windows / Intel Core i5-12600KF / MSVC 19.44 Release / NVIDIA RTX 2080 Ti，驱动 610.62；960×640、5000 精灵、16 帧预热、80 帧采样、每组合两轮。比较同版本 --reference 与默认优化；均关闭阴影/FXAA/图形调试，无交换链呈现。中文版压力场景实际使用系统 msyh.ttc。一次只运行一组 GPU 工作。

以下是每轮 CPU 帧均值/P95 再取两轮算术平均，单位毫秒；不是合并全部样本后的总体 P95。渲染线程模式仍等待 render 的 CPU 提交，GPU 可以继续执行。表内时间含更新、文字批次、提取、抽样拾取及 render；完整墙钟/FPS 与 GPU 时间另存于 CSV。

均值改善更明显的是稳定场景的 CPU 提取/准备与 Vulkan 资源流入。动态场景采用固定精灵几何共享和 BVH 重拟合后，避免了最初全量重建索引的回退。不同后端/线程的收益不同，原始 CSV 同时保留单线程结果。

OpenGL 的小分块批次均值未观察到改善，变化也较接近波动范围；这类场景可通过 spatialCulling 开关对照，不能把某个大场景的收益外推到所有批次粒度。

- opengl 中文压力场景：当前图集像素载荷 47,185,920 → 11,796,480 字节；80 帧新资源 CPU 上传 100,674,048 → 15,039,205 字节（两轮均值）。
- vulkan 中文压力场景：当前图集像素载荷 47,185,920 → 11,796,480 字节；80 帧新资源 CPU 上传 100,674,048 → 15,039,205 字节（两轮均值）。
- Vulkan 数组流入：80 帧资源传输提交 580 → 10，上传等待 580 → 0；普通绘制提交及帧槽等待不计入。

完整矩阵两种模式各保存 48 张终帧 PNG，其中同后端/线程/轮次的 48/48 对 PNG 文件字节完全相同；专项 GPU 测试还验证更新后回放旧页面的像素一致。分块整体界限快路径恢复后，仅 batch 档位按同参数重新采样，汇总 CSV 使用该档位的新结果。

文字场景每帧引入 24 个此前可能没见过的 CJK 字符，FreeType SDF 栅格化仍占用大量 CPU。R8 与局部更新显著减少图集载荷/上传，未消除首次栅格化成本；实际游戏应在加载阶段预热常见字符。暂存池会保留可复用内存，CSV 的受管理内存峰值包含池载荷，不能将其当驱动实际显存。

原始数据在本地 build/windows/benchmarks：optimization-before.csv 为修改前历史采样；optimization-final.csv / optimization-final-reference.csv 为完整矩阵，optimization-final-batch*.csv 为分块补采；optimization-comparison-optimized.csv / optimization-comparison-reference.csv 为用于本表的 48 行汇总。各 CSV 的 .environment.txt 保存环境，PNG 在相应同名目录。构建产物不纳入 Git，报告保留结果、口径与复现命令。

这些是当前设备与特定负载的数据，不表示引擎最大容量；功能回归不设置 FPS 门槛。
